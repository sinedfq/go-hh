# Запуск Trudomix через Docker

Нужен запущенный Docker Desktop с Linux-контейнерами. Go и Node на компьютере
для обычного запуска не нужны. Команды выполняются из корня проекта.

На этом Windows-компьютере достаточно:

```powershell
.\scripts\stack.ps1
```

Скрипт собирает сайт и API, запускает PostgreSQL, применяет миграции и ждёт
готовности сервисов. Если существует `.cache/firebase-service-account.json`,
подключает локальные push-уведомления. Серверный ключ не попадает в образ.

- Сайт: **http://localhost:3000**.
- API: **http://localhost:8081**; проверка **http://localhost:8081/health**.
- PostgreSQL: `localhost:5432`, база `gohh`.
- Для Android-эмулятора контейнерный API: `http://10.0.2.2:8081/`.

Порт 8081 позволяет сохранить уже работающий обычный Go-сервер на 8080.
Контейнерные порты по умолчанию доступны только с этого компьютера.

Управление:

```powershell
.\scripts\stack.ps1 -Action status
.\scripts\stack.ps1 -Action logs
.\scripts\stack.ps1 -Action down
```

После изменения исходников снова выполните `.\scripts\stack.ps1`.

## Docker Compose без скрипта

```sh
docker compose up -d --build --wait
docker compose logs -f api frontend migrate
docker compose down
```

Для push с уже настроенным локальным ключом:

```sh
docker compose -f docker-compose.yml -f docker-compose.firebase.yml up -d --build --wait
```

Без дополнительного файла приложение запускается с обычными уведомлениями сайта,
а отправка FCM отключена. Приватный ключ восстанавливается отдельно при клонировании;
подробнее в [PUSH_SETUP.md](PUSH_SETUP.md).

## Данные и настройки

PostgreSQL и загруженные изображения хранятся в именованных томах
`postgres_data` и `uploads_data`. `down` сохраняет их. Не добавляйте `-v`,
если хотите сохранить данные.

При запуске содержимое локальной `uploads` копируется в том без перезаписи
существующих файлов; новые загрузки контейнера остаются в томе. Старые локальные
фотографии и логотипы продолжают работать. При возврате к запуску API без Docker
сначала скопируйте новые фотографии обратно:

```sh
docker compose cp api:/app/uploads/. ./uploads/
```

Для этой рабочей папки сохраняется существующий том `go-hh_postgres_data`.
Не меняйте имя Compose-проекта через `-p`, если хотите использовать ту же базу.
При запуске на другом компьютере миграции создадут новую базу и исходные вакансии.
Миграция 026 добавляет недостающие в старой цепочке поля `users.role` и
`users.company_id`, сохраняя существующие значения на настроенной базе.

По желанию скопируйте `.env.example` в `.env` и измените порты, параметры БД
и `JWT_SECRET`. Если пароль содержит символы, значимые для URL, дополнительно
задайте `DOCKER_DATABASE_URL` с URL-кодированным паролем; в `POSTGRES_PASSWORD`
оставьте исходный пароль.
Примерные значения предназначены для локальной разработки.

Сайт работает через Nginx: `/api` и `/uploads` проксируются в API, обновление
страницы по внутреннему адресу возвращает React-приложение. Образы не содержат
локальные credentials, Android, `node_modules` или пользовательские загрузки.
ML-рекомендации используют отдельно запущенный сервис по `ML_SERVICE_URL`;
обычный поиск, чаты, компании и резюме работают без него.

## Проверка на отдельной базе

В CI контейнеры собираются с нуля, после чего `scripts/docker-smoke.mjs`
проверяет сайт, маршрутизацию, API, регистрацию, компанию и загрузку логотипа.
Скрипт создаёт тестовый аккаунт; запускайте его только на отдельной тестовой базе.
Готовность PostgreSQL и завершение миграций учитываются через
[зависимости Compose](https://docs.docker.com/compose/how-tos/startup-order/).
