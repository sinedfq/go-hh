# Запуск Trudomix на Windows

Все команды выполняются в PowerShell из `D:\Projects\go-hh`.

## Быстрый запуск всего проекта

```powershell
.\scripts\stack.ps1
```

Откройте **http://localhost:3000**. Docker собирает фронтенд и API, запускает
базу и применяет миграции; локальный Firebase подхватывается автоматически.
API контейнера доступен на 8081. Остановка: `.\scripts\stack.ps1 -Action down`.
Подробности, параметры и хранение данных — в [DOCKER.md](DOCKER.md).

Общая ветка разработки — `dev`. Порядок работы с новыми ветками и автоматические
проверки описаны в [GIT_WORKFLOW.md](GIT_WORKFLOW.md).

Подготовленный сервис проверки телефона и тестовый режим SMS описаны
в [PHONE_OTP.md](PHONE_OTP.md). По умолчанию доставка отключена.

## Веб-фронтенд

```powershell
cd frontend
npm install
npm run dev
```

Откройте локальный адрес, напечатанный Vite в терминале. Если порт 5173 занят,
Vite выберет следующий свободный. Запросы `/api` и `/uploads` проксируются на
локальный бэкенд порта 8080. Проверки: `npm test`, `npm run lint`, `npm run build`.
Production-сборка находится в `frontend/dist`.

## Бэкенд

```powershell
docker compose up -d postgres
go run .\cmd\api\
```

Если настроена локальная конфигурация Firebase, используйте вместо `go run`:

```powershell
.\scripts\api.ps1 -RequirePush
```

Команда загружает параметры проекта и путь серверных credentials из
`.cache/push.local.json`. Этот файл и серверные ключи не входят в Git.

API слушает порт 8080. Проверка: `http://localhost:8080/health`.
Если порт уже занят вашим старым процессом Go, перезапустите этот процесс после обновления исходников.
Для параллельного запуска можно задать `HTTP_ADDR=:8081` и передать Android соответствующий `ApiBaseUrl`.
По умолчанию используется локальная PostgreSQL `gohh` из `docker-compose.yml`.
Для другого подключения задайте `DATABASE_URL` в окружении.
Миграции находятся в `migrations/`; используйте Goose с PostgreSQL.
В Docker миграции применяются автоматически по 027 включительно:
`device_tokens`, условия вакансий, профили компаний, сохранённые поиски и история откликов.
Не применяйте разделы Down из миграций при обычном обновлении.

`ML_SERVICE_URL` нужен для ML-рекомендаций; обычный поиск вакансий работает через PostgreSQL.
Если ML-сервис не запущен, API выполняет базовый подбор по навыкам, должности,
опыту и удалённому формату (`model_used: basic-skills-v1`). Ожидание ML ограничено
8 секундами, резервный результат кешируется на 45 секунд. После восстановления
ML следующий пересчёт снова использует модель; «Обновить» пересчитывает сразу.
Подписки на поиски проверяются запущенным API каждые 30 секунд; новые совпадения
появляются в колокольчике сайта. Уже существовавшие до подписки вакансии не уведомляют.
Сквозные проверки новых возможностей: задайте `TRUDOMIX_TEST_DATABASE_URL` и выполните
`go test ./cmd/api -run TestProductGrowthFlows -v` — используются отдельные временные схемы.
Для production задайте собственный `JWT_SECRET`, настройте HTTPS и параметры подключения БД.

## Эмулятор

На этом компьютере настроен рабочий профиль `Trudomix_API34` и отдельный SDK
`D:\Android\Sdk-Trudomix` с Emulator 36.5.11. Основной SDK и старый `Pixel_7` сохранены.
Настройки конкретного компьютера находятся в `android/emulator.local.json` (исключён из Git).

```powershell
.\scripts\emulator.ps1 -Visible -WaitForBoot
```

Альтернатива: Android Studio → Device Manager → кнопка запуска у `Trudomix_API34`.
Если Android Studio использует старую установку Emulator, выберите Android SDK Location
`D:\Android\Sdk-Trudomix` в SDK Manager. Для проекта этот путь уже указан в `android/local.properties`.
Скрипт использует 2560 МБ RAM, два ядра и SwiftShader; при необходимости доступны `-MemoryMb` и `-Cores`.
Он не загружает старые snapshots, записывает логи в `.cache` и с `-WaitForBoot` проверяет готовность Android.
Первый запуск чистого Google Play-образа может занимать несколько минут.
Если AVD отсутствует, создайте Pixel в Device Manager с образом Google Play или Google APIs, API 34/35.
Для FCM нужны Google Play services; для аппаратного backdrop blur — Android 12 или новее.

Дождитесь рабочего стола Android. Затем:

```powershell
.\scripts\android.ps1 -Action run
```

Скрипт собирает APK, устанавливает приложение и открывает его.
По умолчанию Android обращается к компьютеру по `http://10.0.2.2:8080/`.
Бэкенд должен продолжать работать в отдельном терминале.
Если ранее запускался эмулятор без окна для тестов, сначала закройте этот экземпляр:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" -s emulator-5554 emu kill
```

Перед выполнением проверьте серийный номер через `adb devices`, если устройств несколько.

## Физический телефон

В debug-APK адрес сервера теперь можно менять без пересборки: на экране входа нажмите
**Подключение к серверу**, либо откройте **Профиль → шестерёнка → Подключение к серверу**.
На экране ошибки начального подключения эта кнопка тоже доступна.
Укажите `http://192.168.0.4:8080/` (текущий Wi-Fi-адрес этого компьютера), затем
**Проверить и сохранить**. Приложение проверит `/health`; при смене адреса потребуется войти заново.
Телефон должен находиться в той же Wi-Fi-сети. `10.0.2.2` работает только в эмуляторе.
Для проверки откройте `http://192.168.0.4:8080/health` в браузере телефона: ожидается `{"status":"ok"}`.

На компьютере разрешён входящий TCP 8080 только через выбранный сетевой интерфейс,
для текущего профиля сети и из `LocalSubnet` (правило `Trudomix-API-WiFi-8080`).
Если IP или профиль сети изменится, обновите правило из PowerShell **от имени администратора**:

```powershell
.\scripts\allow-phone-api.ps1 -InterfaceAlias 'Беспроводная сеть'
```

Включите USB debugging и подтвердите доверие компьютеру.
При USB-подключении можно использовать:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8080 tcp:8080
.\scripts\android.ps1 -Action run -ApiBaseUrl 'http://127.0.0.1:8080/'
```

Либо укажите LAN-адрес компьютера через `-ApiBaseUrl 'http://АДРЕС:8080/'`.
Адрес обязательно заканчивается `/`. Проверьте доступность порта в Windows Firewall.
HTTP разрешён только в debug-сборке. Для release задайте `-PPRODUCTION_API_BASE_URL=https://ваш-домен/`.
Адрес `.example`, оставленный по умолчанию в release, не является работающим сервером.

## Проверки

```powershell
go test ./...
.\scripts\android.ps1 -Action test
.\scripts\android.ps1 -Action device-test
```

Для PostgreSQL-интеграционного теста задайте `TRUDOMIX_TEST_DATABASE_URL`.
Тест создаёт собственную временную схему `codex_chat_*`, проверяет доступ участников
и посторонних к истории, отправке, прочтению и typing, затем удаляет только свою схему.
Пользователь тестовой БД должен иметь права на создание схемы.

Android-тесты проверяют DTO-контракты и то, что касания панели навигации
не активируют содержимое под ней, а вкладки, карта и область вне панели доступны.

Скрипт использует `.cache/gradle` в проекте: это позволяет обойти проблему
JDK 17/Gradle worker с кириллицей в пути пользовательского кэша на этой машине.
При первом запуске wrapper может загрузить Gradle и зависимости. Нужен JDK 17 и SDK 35.

Для APK используйте `.\scripts\android.ps1 -Action build`: скрипт резервирует
новый номер в `.cache/android-build-number.txt`, передаёт его в `versionCode`
и сохраняет файл `Trudomix-1.0-build-0002-debug.apk` (число меняется при сборках)
в `android/app/build/outputs/apk/debug/`. Номер также виден в настройках приложения.
Неудачная попытка может оставить пропуск в нумерации. Проверки `-Action test`
и `-Action device-test` номер не увеличивают.

Для ручного Gradle-запуска номер можно задать через `-PBUILD_NUMBER=123`;
без параметра используется текущий локальный номер, либо 1 при первом запуске.
CI использует `github.run_number` и добавляет его к имени артефакта.
Обычный `app-debug.apk` сохраняется для совместимости инструментов Android.

## Firebase: выполнить вручную

Подробная инструкция для первого подключения: [PUSH_SETUP.md](PUSH_SETUP.md).
В текущей сборке без `google-services.json` доставка FCM не включена.
В **Профиль → шестерёнка → Уведомления** доступны разрешение, состояние регистрации,
проверка готовности сервера и локальный тест отображения. Локальный тест не проверяет доставку FCM.

1. Создайте или выберите проект в Firebase Console.
2. Добавьте Android-приложение с package name `com.example.trudomix`.
3. Скачайте `google-services.json` и положите в `android/app/google-services.json`.
4. Проверьте включение Firebase Cloud Messaging API (HTTP v1) для проекта.
5. На сервере настройте Application Default Credentials: например, задайте
   `GOOGLE_APPLICATION_CREDENTIALS` как путь к service account JSON вне репозитория.
6. Задайте `FIREBASE_PROJECT_ID` перед запуском Go API.
7. Пересоберите Android, войдите в аккаунт и разрешите уведомления.
8. На втором устройстве войдите другим участником, отправьте сообщение и измените статус отклика.
   Проверьте получение в foreground/background и переход по нажатию.

Без Android-конфигурации приложение собирается и работает с REST, но FCM не активируется.
Без `FIREBASE_PROJECT_ID` сервер явно сообщает в логах, что FCM отключён.
Приватный service account не добавляйте в Git. `google-services.json` также исключён из Git.
При смене пользователя токен устройства перепривязывается, при выходе удаляется регистрация.
Сервер поддерживает несколько устройств и удаляет токены, признанные Firebase недействительными.

## Карта и геокодинг

Кнопка прицела запрашивает геопозицию через разрешение Android. Разрешение «При использовании»
и приблизительное местоположение поддерживаются; фоновый доступ не запрашивается.
Если определение по Wi-Fi недоступно, разрешите точное местоположение для GPS.
При выключенной геолокации или отказе карта продолжает работать с вакансиями.
Тема подложки следует теме приложения. Используется фильтр цвета слоя карты JS API 2.1;
для штатной темы API 3 потребуется доступный ключ с настроенным HTTP Referer
([требования Яндекса](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html)).

Android использует Яндекс.Карты JavaScript API 2.1 в WebView, как существующий frontend,
и показывает только реальные координаты API. Нажатие маркера открывает карточку вакансии.
При сборке берётся публичный ключ JS API из `frontend/src/components/common/YandexMap.jsx`;
переопределить его можно Gradle-свойством `YANDEX_MAPS_API_KEY`. Ограничения ключа должны
разрешать используемое приложение; нужен доступ к интернету и сервисам Яндекса.
При ошибке карты доступны повторная загрузка и переход во внешние Яндекс.Карты.
Для определения координат по адресу настройте `YANDEX_GEOCODER_API_KEY` на Go-сервере.
Встроенный fallback-ключ удалён. Координаты также можно ввести вручную при публикации вакансии.

## Проверка интерфейса

- Новые фильтры требуют перезапуска Go API после обновления исходников.
  Поиск поддерживает `company`, `has_coordinates=true`, `sort=newest|oldest|popular|title`;
  в `experience` несколько значений разделяются `|` и объединяются по «ИЛИ».
- Начните вводить город: подсказки берутся из вакансий сервера. Выберите грейд и/или стаж,
  навыки, компанию, формат работы, сортировку, затем нажмите «Показать вакансии».
  Закрытие панели не применяет изменения. Сброс очищает черновик фильтров.
- В редакторе резюме выберите подсказку или используйте своё значение. Добавьте навык,
  сохраните и откройте резюме снова. Проценты у полей совпадают со шкалой в профиле;
  один раздел контактов заполняется телефоном или Telegram, их вклад не суммируется.
- На карте нажмите «Моё местоположение», проверьте разрешение/отказ и выключенный GPS.
  В обеих темах убедитесь, что читаются карта, карточки и маркеры.

- Вход: мягкий анимированный фон, появление формы, переходы между экранами и вкладками.
  На небольшом экране и при открытой клавиатуре форма прокручивается; на широком — два столбца.
- Главный экран: явные цвета заголовка и карточек для обеих тем, поиск и фильтры в прокручиваемой области.
  При достаточной ширине вакансии располагаются в несколько колонок; крупный шрифт увеличивает минимальную ширину карточки.
- Профиль → шестерёнка → иконка приложения: 24 варианта из `icons/`, по умолчанию `09_dark_waves` («Тёмные волны T»).
  Меняется иконка в лаунчере; её обновление зависит от лаунчера и может занять несколько секунд.
  Исходные PNG сохранены; XML-обёртки и обрезка при отображении убирают внешние полосы рамки.
- Вакансии: поиск, фильтры, избранное, загрузка следующей страницы, детали и отклик.
- Прокрутите список: карточки проходят за стеклянной панелью; последняя доступна целиком.
- Нажатия на вкладки и карту не должны открывать карточку позади панели.
- Профиль → шестерёнка → тема: проверьте светлую/тёмную, перезапустите приложение.
- Профиль → добавить/изменить фото; резюме → добавить/изменить фото. Используются разные API.
  Поддерживаются JPG, PNG и WebP до 20 МБ. Перед отправкой откроется кадрирование:
  перетаскивание, масштаб, поворот, сброс и отмена; сохранённая область отправляется
  в JPEG до 1024×1024 и 4 МБ. Фото резюме добавляется после его создания.
- Профиль → моё резюме: создание, просмотр, изменение и контакты.
- Профиль работодателя → кабинет: компания, публикация/редактирование/архив вакансии, отклики и чат.
- Два пользователя: входящие/исходящие сообщения, typing, счётчики и прочтение.
- В чате отображается сопроводительное письмо, а карточка сверху ведёт в вакансию.
- Отклики: фильтры «Все», «В работе», «Принятые», «Отказы», раскрытие письма,
  кнопки чата/вакансии и подтверждение отзыва отклика.
- Профиль: реальные просмотры резюме, число откликов, принятые отклики и избранное;
  плитки открывают соответствующие разделы. Заполненность резюме вычисляется по его полям.
  При недоступности статистики показано «—» и действие повтора, а не выдуманный ноль.
- Карта: поиск, фильтр офисных вакансий, группировка маркеров, кнопки масштаба,
  показ всех вакансий, карточка выбранной вакансии и переход к маршруту в Яндекс.Картах.

## Новые экраны и демо-наполнение

- Android открывает «Главную». Внизу: главная, поиск, отклики, чаты и карта.
  Профиль — аватарка в шапке; при прокрутке вверх она доступна в плавающей панели.
  Обновление списков: потянуть вниз. «Мои поиски» есть на главной и в поиске.
- «Моё резюме → История работы»: добавить места работы с датами. Общий стаж
  считается автоматически, без удвоения пересекающихся периодов. «Скачать PDF»
  сохраняет оформленное резюме с аватаркой слева через системный выбор папки.
- В описаниях вакансий поддерживаются Markdown и изображения. При публикации
  есть предпросмотр и загрузка картинки до 4 МБ (JPG/PNG/WebP).
- Демонстрационные записи добавляются командой из корня проекта:

```powershell
go run ./cmd/seed-demo
```

Команда добавляет 6 вымышленных компаний и 24 вакансии. Повторный запуск
не создаёт дублей и не удаляет существующие данные. Старый cmd/seed удаляет
вакансии — для безопасного дополнения базы используйте именно seed-demo.
Сведения об IT-аккредитации — отметка компании, доступная по нажатию на IT.
