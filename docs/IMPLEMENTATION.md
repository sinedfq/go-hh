# Изменения Trudomix

## Рабочие экраны и проверка доставки push

- Firebase-проект `trudomix-dev-0117961b93` создан и подключён к локальным Android
  и Go. Реальная доставка Go → FCM → Android проверена на эмуляторе. Серверный ключ
  хранится в `.cache`, ограничен правами текущего пользователя Windows и SYSTEM
  и имеет доступ только к Cloud Messaging. Analytics и платные сервисы не включались.

- Создание/редактирование вакансии разделено на блоки: требования, оплата,
  задачи и расположение. На широком экране справа есть предпросмотр карточки.
  Введённый город сразу попадает в форму и предпросмотр, даже без выбора подсказки.
- «Мои вакансии»: сводка публикаций/просмотров/архива, поиск по должности и городу,
  отдельные вкладки активных вакансий и архива, восстановление и подтверждение удаления.
- «Мои отклики»: общие карточки статистики, поиск по компании и должности,
  компактные фильтры статуса, единое оформление истории отклика и действий.
- Статистика публичной компании использует те же карточки с иконками.
- В Android добавлена проверка настоящей доставки через сервер. Новый
  `POST /api/devices/test` разрешает отправку только на устройство текущего
  пользователя; диагностическое сообщение не создаёт запись в ленте событий.
- `scripts/api.ps1` запускает API с локальной конфигурацией push из
  `.cache/push.local.json`, если она настроена. `-RequirePush` останавливает запуск,
  если локальная конфигурация и переменные окружения отсутствуют.

## Страница компании и уведомления о событиях

- Публичная страница компании сайта использует общие цвета, карточки и типографику
  в обеих темах. Добавлены адаптивная шапка, блоки команды/найма/преимуществ,
  зарплаты и условия в вакансиях, переход с клавиатуры, повтор загрузки при ошибке.
- Android разделяет сообщения, просмотры резюме и ответы по откликам на отдельные
  системные каналы. Для сообщений доступна история в развёрнутой карточке;
  просмотры резюме по умолчанию без звука. Настройки каждого канала доступны
  из настроек приложения. Содержимое скрывается на заблокированном экране.
- Переходы из уведомлений: переписка → чат, просмотр резюме → моё резюме,
  ответ работодателя → отклики, новый отклик работодателю → управление компанией.
- Сервер отправляет push после сохранения события в базу: просмотры резюме,
  ответы по откликам, приглашения и изменения вакансий. Повторный просмотр
  тем же работодателем в течение суток не создаёт ещё одно уведомление.
  Сообщения содержат имя собеседника/компании и короткий текст.
- Для реальной доставки из интернета нужна локальная конфигурация Firebase;
  она уже подключена в рабочей копии, но не хранится в Git. См. PUSH_SETUP.md.

## Уведомления открытого чата и проверки GitHub

- Android убирает уведомление переписки при открытии чата и не показывает
  повторные уведомления, пока этот чат находится на переднем плане. Уведомления
  других переписок продолжают работать. При уходе с экрана или сворачивании
  приложения уведомления этой переписки снова разрешены.
- Загрузка сообщений и отметка прочтения выполняются, пока экран чата находится
  в состоянии RESUMED. Проверки отображения уведомлений покрывают открытие,
  другой чат и возвращение в фон.
- GitHub Actions проверяет Go с отдельной PostgreSQL, сайт и сборку Android.
  Порядок работы через `dev` описан в GIT_WORKFLOW.md.

## Главная Android, мои поиски, Markdown и новый PDF

- Нижняя навигация Android: главная, поиск, отклики, чаты; карта остаётся
  отдельной кнопкой. Профиль открывается через аватарку в общей шапке.
  Когда шапка уходит за экран, при прокрутке вверх появляется плавающая
  кнопка профиля. Кнопки обновления заменены жестом «потянуть вниз».
- На главной: приветствие, отклики/просмотры, заполненность резюме,
  переход в «Мои поиски» и свежие вакансии. У работодателя — управление компанией.
- «Мои поиски» Android работают с тем же API, что сайт: сохранение текущих
  условий, просмотр, восстановление всех фильтров (включая офис и зарплату),
  удаление с подтверждением. Добавлены зарплатные поля, валюта, занятость и график
  в мобильную панель фильтров. Лимит сервера — 20 поисков.
- Общий стаж считается на сервере по датам работ. Пересекающиеся периоды
  объединяются, будущие и некорректные периоды не учитываются. Грейд остаётся
  отдельным полем. В Android можно добавлять и удалять места работы; удаление
  на сервере проверяет владельца. Итог доступен на сайте, в Android и PDF.
- Новый PDF: левая светлая колонка с аватаркой, справа все сведения; синие
  акценты, номера страниц, кириллица и переносы. В PDF попадают только
  локальные изображения из uploads; отсутствие фото не мешает выгрузке.
- IT-значок уменьшен до 18–19 px, выровнен с названием компании. По нажатию
  открывается пояснение. На сайте окно вынесено поверх карточек и ограничено
  размерами экрана. Статус по-прежнему указывается компанией.
- В редакторах вакансий сайта и Android есть Markdown, предпросмотр и загрузка
  JPG/PNG/WebP до 4 МБ. POST /api/vacancies/images разрешён работодателю
  собственной компании. Ссылки на загруженные картинки сохраняются в Markdown.
  Сырой HTML не исполняется. Android рисует Markdown нативными Compose-компонентами.
- Оптимизация Android: модели вкладок создаются по мере открытия, избранное
  кешируется на 60 секунд при вводе поиска, независимые запросы идут параллельно,
  разбор Markdown выполняется вне UI-потока. Убран повторный запрос личности
  при старте и повторная загрузка главной; polling работает в активном lifecycle.
- Наполнение: cmd/seed-demo добавляет 6 вымышленных компаний и 24 вакансии
  с логотипами, иллюстрациями, городами, условиями и зарплатами. Данные отмечены
  как демонстрационные. Команда идемпотентна, не удаляет существующие записи.


## Тёмная тема, условия вакансий, IT и PDF

- Светлые поверхности карточек компаний, окон просмотра/редактирования резюме,
  форм работодателя и уведомлений в тёмной теме используют палитру Android:
  фон `#0d1117`, карточки `#161b22`, голубые акценты. Добавлены адаптивные сетки.
- Android читает диапазон зарплаты, валюту, признак «до вычета налогов», занятость
  и график из API. Город, грейд и «Удалённо»/«В офисе» собраны в общую строку
  с переносом. Условия показаны в поиске, деталях вакансии, компании и на карте.
- В веб-форме компании есть переключатель IT-аккредитации. Поле хранится
  в `companies.profile`, миграция поверх 025 не требуется. Значок IT в круге
  показан в компаниях и вакансиях сайта/Android. Это статус, указанный самой
  компанией, без автоматической проверки реестра.
- В профиле сайта и на экране «Моё резюме» Android есть «Скачать PDF».
  `GET /api/my-resume/pdf` доступен авторизованному владельцу. Контакты,
  навыки, описание и история работы экспортируются с встроенными открытыми
  Go-шрифтами (кириллица), переносами и нумерацией страниц. Android сохраняет
  файл через системный выбор папки, без разрешения на доступ ко всему хранилищу.
- Проверки: Go (включая изолированную PostgreSQL), веб-сборка и JS-тесты,
  Android APK/JVM; PDF проверяется реальным Android PdfRenderer.

## Развитие веб-версии: пять последовательных этапов

1. **Главная.** Новый стартовый экран для гостя, кандидата и работодателя: настоящие
   показатели откликов/сообщений/просмотров, заполненность резюме, рекомендации или
   свежие вакансии, последние отклики. На телефоне основные разделы помещаются
   в нижней панели, карта, свайпы и подписки доступны через «Ещё».
2. **Зарплаты и условия.** Работодатель задаёт месячный диапазон, RUB/USD/EUR,
   «на руки»/«до вычета налогов», занятость и график. Данные сохраняются при
   создании/редактировании вакансии и показаны в поиске, на главной и в вакансии.
   Фильтры сравнивают диапазоны в выбранной валюте без конвертации/пересчёта налогов.
   Старые вакансии без этих полей показывают «Зарплата не указана».
3. **Компании.** Редактирование основных сведений, команды, преимуществ и этапов
   найма; галерея до шести JPG/PNG/WebP по 4 МБ. Публичная страница показывает
   заполненные разделы. При переименовании компании обновляется название в вакансиях.
4. **Сохранённые поиски.** До 20 подписок на пользователя, сохранение всех фильтров,
   открытие и удаление. Сервер каждые 30 секунд проверяет новые вакансии после
   создания подписки и создаёт уведомления в колокольчике сайта. Повторных уведомлений
   об одной вакансии в одной подписке нет; клик открывает вакансию.
   Это уведомления внутри сайта, новые каналы email/Web Push в этом этапе не добавлялись.
5. **История отклика.** Отправка, просмотр, приглашение/отказ, комментарий кандидату,
   дата собеседования в часовом поясе устройства. Изменения записываются триггером
   в одной транзакции со статусом. Работодатель редактирует детали в откликах,
   кандидат читает их в «Моих откликах». Нет доступа к чужим откликам.
   Для старых статусов без даты отображается отсутствие точной даты.

- Добавочная миграция `025_product_growth.sql` применена к локальной базе в транзакции
  с записью версии Goose; существующие данные сохранены. Старые клиенты Android
  совместимы с дополнительными JSON-полями, их интерфейс в этом этапе не расширялся.
- Локальный API обновлён: `.cache/trudomix-api-product-final.exe`, порт 8080;
  логи — `.cache/api-product.stdout.log` и `.cache/api-product.stderr.log`.
- Проверки: Go-тесты, изолированные сценарии PostgreSQL (зарплаты, права, лимит галереи,
  будущие совпадения и отсутствие дублей, история и смена роли), JS-тесты и сборка.
  Основные новые веб-экраны проверены в Chromium WebView на мобильной и широкой
  компоновках с API-фикстурами; пользовательские сообщения/отклики при этом не отправлялись.

## Рабочая загрузка логотипа и логотипы в Android

- На порту 8080 была запущена старая версия API без `/api/my-company/logo`
  (на момент диагностики маршрут возвращал 404). Собрана и запущена актуальная
  версия `.cache/trudomix-api.exe`; логи — `.cache/api.stdout.log` и `.cache/api.stderr.log`.
  Vite использует явный адрес upstream `127.0.0.1:8080` для API и uploads.
- Реальная загрузка проверена через Vite на 5173: временный работодатель,
  создание компании, POST логотипа — 200, получение изображения через `/uploads` — 200,
  байты совпадают с исходным файлом. Созданные тестовые данные и файл удалены.
- API передаёт `company_logo` в поиске, списках вакансий, избранном, рекомендациях,
  карточке вакансии и вакансиях компании. Логотип читается из `companies.logo_url`,
  поэтому замена не требует обновления каждой вакансии.
- Android использует общий `CompanyAvatar` в карточках вакансий, подробной вакансии
  и на странице компании. Относительный путь разрешается относительно выбранного
  сервера; при отсутствии/ошибке загрузки остаётся иконка компании.
- Проверено: Go-тесты с отдельными схемами PostgreSQL, production-сборка фронтенда,
  debug APK, 20 JVM-тестов и UI-тест загрузки относительного URL/ошибочного логотипа.

## Полные веб-фильтры, аватар компании и favicon

- Фильтры веб-поиска перенесены в отдельную адаптивную панель с прокруткой
  и постоянно доступными кнопками. Добавлены город/компания с подсказками,
  любой/удалённый/офисный формат, несколько грейдов и значений стажа в годах,
  навыки, наличие адреса на карте и сортировка — как в Android.
  До применения изменения хранятся в черновике. Все параметры сохраняются в URL;
  `company_filter` не конфликтует с параметром страницы компании `company`.
- В разделе работодателя «Моя компания» можно добавить или заменить аватар.
  После создания компании пользователь остаётся на её странице для загрузки логотипа.
  Используется `POST /api/my-company/logo` с multipart-полем `photo`; компания
  определяется по авторизованному работодателю. Обновляется существующее поле
  `logo_url`, которое показывают публичные карточки компаний. Миграция не нужна.
- При загрузке проверяются фактический тип JPG/PNG/WebP и размер до 4 МБ.
  При ошибке записи в БД новый файл удаляется. Проверены отсутствие авторизации,
  роль, отсутствие компании, поддельное изображение и запрет изменения чужой компании
  в отдельной временной схеме PostgreSQL без изменения пользовательских данных.
- Иконка вкладки браузера и apple-touch-icon используют «Тёмные волны Т».
  Для нового маршрута загрузки требуется перезапуск работающего бэкенда.

## Редактор фото, появляющийся поиск и основные веб-экраны

- Android: редактор аватара больше не находится внутри прокручиваемого контейнера,
  который перехватывал жесты. Увеличена область предпросмотра, сохранение перенесено
  в компактную верхнюю панель. Поворот изображения выполняется вне UI-потока.
  Отмена не отправляет фото; сохраняется выбранный участок изображения.
- Android: при прокрутке списка вверх появляется поиск с кнопкой фильтров без текста.
  При прокрутке вниз панель скрывается, в том числе после фокусировки поля поиска.
- Веб: обновлены вход/регистрация, поиск, чат и профиль в бело-синем стиле, включая
  тёмную тему и мобильную компоновку. Добавлены аватарки и имена отправителей,
  понятные сообщения ошибок и реальные показатели профиля с повтором загрузки.
  Загрузка фото проверяет формат и размер; повторный выбор того же файла работает.
- Веб-поиск выполняет запрос при вводе с задержкой; предыдущий запрос отменяется.
  Сброс фильтров снова загружает результаты. Поисковая панель появляется при
  прокрутке вверх; фильтры открываются кнопкой с иконкой.
- Проверки: debug APK и JVM-тесты; UI-тесты кадрирования и поиска на эмуляторе.
  Веб: production-сборка, три теста сообщений ошибок, lint без ошибок
  (предупреждения существующего кода сохранены). Основные экраны проверяются
  в Chromium WebView на мобильной и широкой компоновке с локальными API-фикстурами,
  без отправки сообщений и изменения реальных учётных записей.

## Регистрация без подложки, отдельная геопозиция и кадрирование аватара

- Шапка регистрации прозрачная поверх анимированного фона. Роли расположены
  одной строкой без переноса; на узком экране/при большом шрифте строку можно прокрутить.
- Геопозиция вынесена из верхней карточки в отдельную кнопку слева на карте.
  Сообщения точности/ошибок по-прежнему автоматически исчезают.
- Перед загрузкой фото профиля и резюме открывается редактор: круглый предпросмотр,
  перетаскивание, pinch-to-zoom, ползунок масштаба, поворот, сброс и отмена.
  До подтверждения фото на сервер не отправляется. При ошибке отправки редактор
  остаётся открытым для повторной попытки.
- Фото JPG/PNG/WebP до 20 МБ читается с ограничением памяти, корректируется EXIF-ориентация.
  Выбранная квадратная область экспортируется в JPEG до 1024×1024 и 4 МБ; используются
  прежние multipart API профиля и резюме. Круглая маска применяется при отображении аватара.
- Проверено без эмулятора: debug APK, JVM-тесты (включая геометрию обрезки,
  ограничения перемещения и масштабирование относительно точки касания), компиляция UI-тестов.

## Прокручиваемый профиль, регистрация и временные уведомления

- Шапка профиля перенесена из `Scaffold.topBar` в общий прокручиваемый контент.
  При обновлении уже загруженный профиль не заменяется коротким экраном загрузки,
  чтобы не сбрасывать позицию прокрутки.
- Регистрация оформлена в стиле входа: общий анимированный фон, карточка формы,
  округлые поля, выбор роли, появление формы, прокрутка с клавиатурой и компоновка
  в два столбца на широком экране. Сохранены роли API candidate/employer.
- `AppSnackbarHost` задаёт единый стиль временных сообщений в откликах, вакансии,
  редакторе резюме и на карте: цвета темы, рамка, скругления, иконка и закрытие.
- Геопозиция вынесена из группы масштабирования в верхнюю панель карты.
  Точность и ошибки определения показываются коротким автоматически исчезающим
  сообщением; постоянная карточка точности удалена. Разрешения и отмена запроса
  при уходе с экрана сохранены.
- APK собирается без запуска эмулятора; визуальная проверка на устройстве не выполнялась.

## Единые шапки, аватарки сообщений и возврат на исходную вкладку

- Общий `AppScreenHeader` используется в поиске, откликах, списке чатов, переписке,
  профиле, просмотре/редакторе резюме, настройках, вакансии, компании, кабинете,
  регистрации, логах и панели карты. Типографика, цвета и отступы следуют экрану поиска.
- В сообщениях показаны имя и фото отправителя из `sender_photo`, с инициалами при
  отсутствии/ошибке фото. Для только что отправленного сообщения используется фото
  текущего пользователя до получения полного сообщения очередным обновлением.
- Переписка использует круглые аватарки и карточки в цветах общей темы.
  Просмотр резюме разделён на карточки: основное, опыт, навыки, описание и контакты.
  Добавлена кнопка возврата; грейд больше не отображается с ошибочным суффиксом «лет».
- Выбранная вкладка хранится в `MainTabsViewModel` через `SavedStateHandle`:
  возврат из чата/резюме/настроек не переопределяет её начальным аргументом поиска.
  Состояние вкладок сохраняется отдельно, убран принудительный сброс прокрутки поиска
  при повторном входе. Явный переход из уведомления на отклики сохраняет своё действие.
- Проверено без запуска эмулятора: сборка debug APK, 16 JVM-тестов, компиляция UI-тестов.
  Визуальная проверка этих изменений на устройстве в этом обновлении не проводилась.

## Подсказки, фильтры, геопозиция и единый интерфейс

- Фильтры: город и компания с подсказками, формат «Любой / Удалённо / В офисе»,
  несколько грейдов и требований в годах, навыки, наличие координат и сортировка.
  Изменения остаются черновиком до кнопки применения; работают и в избранном.
  Значения опыта объединяются по «ИЛИ»: грейд не выдаётся за точный стаж.
- Города берутся из доступных вакансий, навыки и должности — из справочников API
  и вакансий. Ошибка справочника не блокирует ручной ввод; есть повтор загрузки.
- Резюме: разделы в едином стиле, поиск/выбор/свой вариант должности, навыка и города.
  Новые должности и навыки после сохранения отправляются в общие справочники.
  Заполненность считается одинаково в профиле и редакторе: 8 разделов по 12,5%.
  Телефон и Telegram дают один общий вклад; дополнительные ссылки и удалённый формат — 0%.
- Список чатов и переписка обновлены: карточки, контекст вакансии, выделяемый текст,
  адаптивные сообщения и поле отправки, сохранены письмо, прочтение и повтор отправки.
- Отклики, чаты и профиль прокручиваются за общей плавающей панелью; стекло прозрачнее,
  меньше размытия и шума, в списках оставлен запас для доступа к последним элементам.
- Геопозиция: кнопка на карте, разрешение Android по нажатию, точная/приблизительная
  позиция, маркер пользователя, ошибки и тайм-аут. Запрос прекращается при уходе с экрана.
  Геопозиция не передаётся Go API и не записывается в профиль.
- Тема карты следует теме приложения. В JS API 2.1 затемняется только слой подложки;
  маркеры и атрибуция Яндекса сохранены. Это адаптация цветов, а не штатный стиль API 3.
  Текущий ключ при проверке API 3 вернул HTTP 403; для перехода нужен подходящий ключ
  с настроенным HTTP Referer в кабинете Яндекса.
- Для новых серверных фильтров нужно перезапустить Go API; миграция БД не требуется.
- Проверено: Go-тесты с PostgreSQL (включая комбинированный поиск и пагинацию),
  13 Android JVM-тестов, 8 UI-проверок новых сценариев/адаптивности, 4 проверки
  откликов/профиля/навигации. Реальная карта загрузилась в обеих темах;
  нажатие маркера открыло вакансию. Получение геопозиции проверено на эмуляторе.

## Карта, отклики, профиль и понятные ошибки

- Стандартная иконка изменена на «Тёмные волны T» (`09_dark_waves`), включая вход и лаунчер.
  Внешние полосы исходных PNG скрываются XML-обёртками и обрезкой при отображении;
  исходные файлы пользователя не перезаписываются.
- Карта: компактные панели, поиск и офисный фильтр, собственные маркеры, кластеризация,
  масштаб/обзор, карточка вакансии и маршрут. Атрибуция Яндекса сохранена.
- Отклики: статусы, фильтры, раскрываемое письмо, дата, отдельные действия,
  подтверждение отмены и блокировка повторного запроса до завершения действия.
- Профиль: данные существующих API статистики, счётчики с переходами и заполненность резюме.
  Недоступные показатели показываются как «—». Статистика работодателя отделена от данных соискателя.
- Ошибки: неверные данные входа, конфликт регистрации, ограничения частоты, тайм-аут и потеря
  соединения отображаются понятным текстом, без HTTP-кодов и технических адресов из исключений.
- FCM payload переведён на high-priority data: уведомление строится приложением с крупной
  выбранной иконкой, текстом нового сообщения, действием и маршрутом в чат.
  Реальная доставка остаётся зависимой от конфигурации Firebase владельца.
- Проверено: 11 JVM-тестов Android, Go-тесты с PostgreSQL и проверка payload; на эмуляторе —
  фильтры/письмо/подтверждение отзыва, переходы статистики, отрисовка и переключение иконок,
  крупная иконка/действие уведомления, загрузка реальной карты и нажатие маркера с открытием вакансии.
