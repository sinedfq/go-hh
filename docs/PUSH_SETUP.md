# Подключение уведомлений Trudomix

В проекте подготовлены Android-клиент, регистрация устройств, канал сообщений и отправка из Go.
Сейчас нет `android/app/google-services.json`. Поэтому реальная доставка FCM ещё не включена.
Кнопка «Тест уведомления» проверяет только отображение на телефоне, а не доставку через интернет.

## Какие события отображаются

- Сообщения: имя собеседника или компании, короткий текст и переход в чат.
- Просмотры резюме: название компании и переход к своему резюме; по умолчанию без звука.
- Отклики: просмотр, приглашение, отказ или обновление собеседования; переход в отклики.
- Для работодателя новый отклик открывает управление компанией.

В настройках уведомлений приложения есть отдельные кнопки «Сообщения»,
«Просмотры резюме» и «Отклики»: они открывают системные настройки канала.
Системная карточка следует теме и оформлению Android на конкретном телефоне.
На заблокированном экране отображается вид события без личного текста.

Для проверки просмотра резюме откройте его из аккаунта работодателя: уведомление
создаётся при первом просмотре этим работодателем за последние 24 часа.
Открытие своего резюме не создаёт уведомление. Для проверки ответов измените
статус отклика в аккаунте работодателя и нажмите уведомление на телефоне кандидата.

## 1. Создать проект Firebase

Откройте [Firebase Console](https://console.firebase.google.com/), создайте проект Trudomix
или выберите существующий. Google Analytics для этой интеграции не требуется.

В настройках проекта добавьте Android-приложение с package name **`com.example.trudomix`**.
Скачайте его `google-services.json` и положите в **`android/app/google-services.json`**.
Этот путь исключён из Git. Не используйте файл от другого package name или проекта.

В настройках Cloud Messaging проверьте, что включён **Firebase Cloud Messaging API (V1)**.
При необходимости перейдите по ссылке управления API в Google Cloud Console и включите его.

## 2. Подключить Go-сервер

В настройках Firebase → Service accounts → Firebase Admin SDK получите JSON-ключ
сервисного аккаунта для серверной отправки сообщений. Храните его **вне репозитория**;
не вставляйте в чат, не включайте в APK и не помещайте в `google-services.json`.
Для production предпочтительны управляемые Application Default Credentials.

В том PowerShell, где запускаете Go API:

```powershell
$env:FIREBASE_PROJECT_ID = 'ID_ПРОЕКТА_ИЗ_FIREBASE'
$env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\путь-вне-проекта\firebase-service-account.json'
go run .\cmd\api\
```

Остановите предыдущий API-процесс в его терминале перед запуском нового на порту 8080.
Используйте ID проекта, а не отображаемое название. Android и Go должны использовать один проект Firebase.
Если сервер пишет `FCM disabled: FIREBASE_PROJECT_ID is not set`, отправка не включена.
Миграция `024_device_tokens.sql` должна быть применена к используемой базе.

## 3. Пересобрать и установить APK

```powershell
.\scripts\android.ps1 -Action build
```

Установите `android/app/build/outputs/apk/debug/app-debug.apk` поверх старой версии на телефон.
При необходимости настройте адрес API через «Подключение к серверу» и войдите в аккаунт.
На телефоне нужны Google Play services, доступ к интернету и к вашему Go API.

В **Профиль → шестерёнка → Уведомления**:

1. Разрешите уведомления. При отказе разрешение можно включить в системных настройках.
2. Нажмите «Повторить подключение», если регистрация не завершилась.
3. Дождитесь сообщения «Устройство подключено к уведомлениям». Проверка учитывает и готовность Go-сервера.
4. Нажмите «Тест уведомления» для отдельной проверки системного отображения.

Проверка использует авторизованный `POST /api/devices/status`; токены в ответах не раскрываются.
Старый Go-процесс не содержит этот маршрут — перезапустите API из актуальных исходников.

## 4. Проверить настоящую доставку сообщения

Войдите на телефоне как получатель, а в веб-приложении или на другом устройстве — как другой
участник той же переписки. Отправьте сообщение именно от другого пользователя.

- И при открытом, и при свёрнутом приложении сообщение отображается через `FirebaseMessagingService`:
  Go отправляет high-priority data-сообщение, Android строит уведомление с выбранной крупной иконкой,
  текстом «Вам пришло новое сообщение» и кнопкой перехода в чат.
  Системная строка состояния использует отдельный монохромный значок, как требует Android.
- Нажатие должно открыть соответствующую переписку после проверки сессии.
- Проверьте звук и разрешение канала «Сообщения и отклики» в настройках Android.

После обновления оформления уведомлений перезапустите Go-сервер из новых исходников:
предыдущая версия отправляет другой тип FCM payload и не использует новый Android-рендерер в фоне.

После системного «Остановить принудительно» сначала откройте приложение заново.
Режим «Не беспокоить» и настройки производителя телефона могут подавлять звук и всплытие.

Инструкции поставщика: [FCM Android setup](https://firebase.google.com/docs/cloud-messaging/android/get-started),
[получение сообщений](https://firebase.google.com/docs/cloud-messaging/android/receive-messages),
[серверная аутентификация](https://firebase.google.com/docs/cloud-messaging/auth-server).
