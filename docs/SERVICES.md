# Сервисы Trudomix

Первый этап разделения: HTTP API и доставка уведомлений запускаются как отдельные
процессы и Docker-контейнеры. Веб и Android продолжают обращаться к тому же API.

| Сервис | Ответственность | Данные |
| --- | --- | --- |
| frontend | Веб-интерфейс и HTTP-прокси | Не хранит серверные данные |
| api | Аккаунты, вакансии, резюме, отклики, чат, лента, OTP | PostgreSQL, uploads |
| notifications | Доставка сообщений и OTP через Firebase | Без БД; только Firebase credentials |
| migrate | Однократные миграции при запуске | PostgreSQL |
| postgres | Постоянные данные | Именованный Docker volume |

Запуск остаётся прежним: `powershell -ExecutionPolicy Bypass -File scripts/stack.ps1 -Action up`.
Скрипт автоматически подключает локальную конфигурацию Firebase. Файл ключа
монтируется только в `notifications`, не копируется в образ и не нужен API.
Без Firebase обычный `docker compose up -d --build --wait` запускает сервис
уведомлений в отключённом режиме; остальной сайт работает.

`notifications` не публикует порт на компьютере. API обращается к
`http://notifications:8082/v1/send` с общим `PUSH_SERVICE_TOKEN`. Перед внешним
развёртыванием замените локальное значение этого секрета в окружении обоих сервисов.
Ответ 410 означает недействительный токен устройства, 503 — временную ошибку.
Установлены таймауты; секреты, OTP и device tokens не попадают в ошибки транспорта.
Повторные попытки автоматически не выполняются, чтобы не дублировать коды.
Записи уведомлений в БД сохраняются до отправки, как и раньше.

При запуске API напрямую через `scripts/api.ps1` сохраняется встроенная доставка
Firebase. Для отдельного процесса запустите `go run ./cmd/notifications`, задав
`FIREBASE_PROJECT_ID`, `GOOGLE_APPLICATION_CREDENTIALS` и `PUSH_SERVICE_TOKEN`;
API передайте `PUSH_SERVICE_URL` и тот же секрет.

Это начало перехода, а не полное разделение доменов. Вакансии, чат и аккаунты пока
находятся в API и используют общую БД. Следующие этапы требуют отдельных контрактов,
владельцев таблиц и миграций данных. Для надёжной фоновой доставки следующим шагом
нужны transactional outbox и очередь с идемпотентными обработчиками. Существующий
ML-сервис по-прежнему подключается через `ML_SERVICE_URL`.
